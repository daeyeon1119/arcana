# ARCANA · 직접 고르는 타로

라이더–웨이트–스미스 78장과 정·역방향, 8종 카드 배열을 사용하는 한국어 타로 성찰 앱입니다. 기본 리딩은 규칙 기반으로 브라우저 안에서 생성합니다. AI API와 계정이 필요하지 않습니다.

유료 서비스는 사용하지 않습니다. 자유로운 질문을 더 잘 이해하기 위한 [무료 로컬 모델 실행·검토](docs/FREE_LOCAL_READER.md)를 별도로 진행하며, 실제 품질과 실행 속도를 확인하기 전에는 기본 앱 해석을 대체하지 않습니다.

## 사용

`index.html`을 브라우저에서 열거나 저장소를 정적 웹 서버로 서비스하세요. 질문 입력 → 배열 선택 또는 자동 추천 → 셔플 → 직접 카드 선택 → 공개 → 리딩 순서로 사용합니다. 자동 분류가 어긋나면 **질문 분야**와 **답변의 초점**을 직접 변경할 수 있습니다.

기록은 현재 브라우저의 저장소에 보관됩니다. 같은 출처에서 열어야 기록이 이어집니다. 다른 기기로 옮길 때는 ‘나의 기록’의 JSON 백업·복원을 사용하세요. **카드는 1909년 RWS “Roses & Lilies” 원본 스캔 78장을 변경 없이 앱에 내장**했습니다. 인터넷 연결이 없어도 같은 원본이 표시되며 자체 일러스트로 바뀌지 않습니다. 글꼴은 연결이 없으면 시스템 글꼴을 사용합니다. 선택적인 언어모델 실험은 리딩 가이드에 있습니다.

## v79 개선

- 결과 대기·확정 결과·아직 하지 않은 연락·이미 받은 답장을 구분합니다.
- 실제 질문의 마지막 요구, 비교 표현, 감정 표현을 반영합니다. 직접 선택한 분야와 초점을 기록에 보존합니다.
- 본문, 카드 근거, 추가 질문, 텍스트 내보내기가 같은 해석을 사용합니다.
- 질문 예시, 글자 수, 추첨 요약, 모바일 터치 영역과 키보드 사용성을 개선했습니다.
- 질문이나 설정을 변경하면 진행 중인 추첨을 초기화하여 이전 질문의 카드와 섞이지 않게 합니다.
- 손상된 기록, 잘못된 카드, 중복 카드, 잘못된 백업을 검사합니다.
- 카드 원본 78장의 JPEG 바이트·해시·크기·출처를 검증하며, 과거 ‘내장 일러스트’ 설정과 생성형 대체 경로를 제거했습니다.

## v80 · 실제 답변 검토와 매트

내용이 다른 새 질문 **320개**로 실제 답변을 생성하고 읽으며, 주체·답장·이미 끝낸 일·잘못된 분야의 조언과 반복 문장을 보완했습니다. [전체 수정 전후 답변](test-results/editorial/review.html)과 [v80 검토 보고서](docs/REVIEW_v80.md)를 확인할 수 있습니다. 개발에 사용한 회귀 자료이며 전문가 동등성 검증은 아닙니다.

카드 매트의 고정된 빈 행·열을 줄이고 화면 너비에 맞게 배치합니다. 펼친 카드 아래의 중복 이름은 제거하고 자리 이름만 남겼습니다. [화면 비교](test-results/mat/)와 [지속 개선 품질 기준](docs/READING_QUALITY.md)을 포함합니다.

## v81 · 카드 연결과 일반화

78장의 정·역방향 세부 주제와 배열 역할을 바탕으로 카드 사이의 긴장·보완·공통 관점을 연결합니다. A·B 비교와 일반 배열의 시간 흐름을 구분합니다. [72개 개발 출력](test-results/synthesis/review.html)과 [개선 보고서](docs/REVIEW_v81.md)를 포함합니다.

특정 질문에서만 좋은 답변을 내는 것을 목표 달성으로 인정하지 않습니다. 구현 고정 뒤 새 표현 54개 × 배열 8종으로 검토했고, 받은 답·결과 대기·복합 요구 등에서 실패가 남았습니다. [첫 평가와 실패 사례](test-results/generalization-v81/review.html)를 보존했으며, 이후 이를 보고 수정한 결과는 회귀 자료로 구분합니다. 전문 해석가 수준을 달성했다는 뜻이 아닙니다.

## v82 · 질문의 근거와 복합 요청

질문에서 요청·사건·주체·발신/수신·부정·계획·전언·시간 범위를 따로 읽는 구조를 추가했습니다. 비교와 결정 후 행동처럼 함께 요청한 관점을 나누어 답하고, 상황을 알 수 없는 질문에는 추첨 전에 한두 문장의 보충 상황을 묻습니다. 빈 질문의 오늘의 성찰은 유지합니다.

[실제 답변 78개와 최초 실패](test-results/question-model/review.html), [개선·검증·남은 한계](docs/REVIEW_v82.md)를 확인할 수 있습니다. 기존 실패 54개와 새 상황 24개를 구분했고, 처음 실패한 후보는 커밋 `4547802`에 보존했습니다. 수정 후 재검사는 회귀 자료이며 전문 해석가와의 독립 검증은 아닙니다.

## 소스와 빌드

`src/arcana79.js`, `src/reading-polish.js`, `src/reading-synthesis.js`, `src/question-model.js`, `src/reading-context.js`, `src/card-mat.js` 및 해당 CSS, `src/original-art.js`가 유지보수 소스입니다. `scripts/build.py`가 저장소의 v78 원본 및 `assets/rws/`의 JPEG를 합쳐 단일 파일 `index.html`을 만듭니다. 질문 모델은 카드·DOM과 독립된 문법 파서이며 범용 언어모델이 아닙니다. 빌드할 때 이미지 SHA-256을 검사하고 과거 일러스트 생성·선택 코드는 제거합니다. 과거 버전은 재현용으로 보존합니다.

```sh
python scripts/build.py
```

## 검증 재현

Node.js와 Python, Playwright 및 Chromium이 필요합니다. 앱 실행 자체에는 Node.js가 필요하지 않습니다.

```sh
npm install
npx playwright install chromium
npm test
```

현재 `npm run diagnose:generalization`은 알려진 v81 실패 54개를 v82에서 회귀 검사합니다. `npm run test:question-regression`은 v82 첫 평가 이후 회귀 자료가 된 24개를 재검사합니다. Git 기록의 이전 앱을 로컬에 재현하며 질문·카드를 외부로 전송하지 않습니다. 과거 버전이 없는 얕은 복제본에서는 Git 기록을 먼저 받아야 합니다.

검사 종료 코드 0이 모든 답변의 품질을 뜻하지는 않습니다. v81 첫 고정 평가는 커밋 `8c611c6`, v82 첫 고정 평가는 `4547802`에서 재현합니다. 최초 평가의 앱·질문 해시와 실패를 덮어쓰지 않습니다. 질문 JSON의 줄바꿈은 LF로 통일해 해시를 계산하며 앱·원본 이미지는 정확한 바이너리 해시를 유지합니다.

설치된 브라우저를 사용하려면 `ARCANA_BROWSER`를 실행 파일 경로로 지정하세요. 기존 Playwright 패키지를 재사용하는 환경에서는 `ARCANA_NODE_MODULES`를 해당 `node_modules` 경로로 지정할 수 있습니다. 테스트는 임시 포트의 로컬 서버를 자체 실행하고 외부 HTTPS 요청을 차단합니다.

- `tests/scenarios.tsv`: 128개 원문 시나리오와 기대 의도·분야·사실 조건
- `test-results/stress-summary.json`: 128 × 8 = **1,024건** 결과, 기존 버전 비교, 카드 영향 검사, 기존 48문항 평가
- `test-results/readings.jsonl.gz`: 질문·배열·정역방향·실제 출력·검사 결과 전체 (gzip JSON Lines)
- `test-results/review-samples.json`: 32건의 상세 검토 표본
- `test-results/ui-summary.json`: 브라우저 사용자 흐름 검사와 브라우저 버전
- `test-results/images-summary.json`: 원본 78장 해시·디코딩, 오프라인 단일 HTML, 도감·리딩·기록 이미지 검사
- `assets/rws/manifest.json`: Wikimedia 원본 URL·권리 표시·픽셀 크기·SHA-1·SHA-256
- [카드 원본과 출처](assets/rws/README.md)
- [개선 및 검토 보고서](docs/REVIEW_v79.md)

자동 검사 통과는 모든 답변의 의미적 정확도나 예측력을 보증하지 않습니다. 128개 개발 질문은 수정 과정에 사용한 회귀 자료이며 독립 평가가 아닙니다. 기존 48문항도 이후 ‘까닭’ 질문의 퇴행 1건 수정에 사용했으므로 최종 결과를 독립 정확도로 해석하면 안 됩니다. 수정 전 평가와 변경 경위는 보고서에 구분했습니다.
