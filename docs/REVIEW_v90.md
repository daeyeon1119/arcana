# v90 요청의 동작·대상·결과물 검토

질문의 분야만으로 조언을 고르기보다 요청한 동작, 직접 대상, 결과물을 함께 분석합니다. 문서의 구성 점검, 관찰 기록의 누락 점검, 자료와 추정 구별, 표현 성찰, 경험 성찰, 비교 방법, 요건 확인, 관계의 약속 조율을 구분합니다. 원문에서 근거가 된 동사·대상의 위치를 남기며 배경에 나온 자료가 실제 요청 대상을 덮지 않게 했습니다. 같은 동작으로 서로 다른 두 대상을 점검하는 요청도 유지합니다.

질문을 추가 입력하는 실제 화면에서 앞선 모호한 요청만 살아남는 오류를 재현했습니다. 요청의 종류가 같아도 원문 범위가 다르면 각각 보존하고, 구체적인 추가 상황을 적용하도록 수정했습니다. [터치 화면 실행 기록](../test-results/request-frame/ui-summary.json)은 추가 상황 입력, 카드 선택·공개·내보내기·저장과 두 대상의 실제 표시를 확인합니다. 합성 390px Chromium 프로필이며 물리적 Android 확인은 아닙니다.

## 개발과 첫 평가의 구분

구현 전에 v89의 HTML을 고정하고 [28개 알려진 질문×8배열의 기준 출력](../test-results/request-frame/baseline/readings.json)을 `78ffd84`에 보존했습니다. 20개는 이전 평가에서 이미 본 질문이며 8개는 작성자의 개발 대조군입니다. [개발 후 실제 비교](../test-results/request-frame/development/review.html)와 직접 읽은 범위는 별도로 기록합니다. 대상 메타데이터가 없던 v89의 계약 실패 수는 의미 정확도 점수가 아닙니다.

구현 `fc60c9efb9c49b6ba11ac64881afa53c78be7bba`를 커밋한 뒤 [새 질문 20개](../tests/request-frame-first.json)를 작성하고 처음 실행한 160개 실제 출력을 `3a8d37a`에 보존했습니다. [첫 비교와 검토](../test-results/request-frame/first/review.html), [직접 읽은 범위](../test-results/request-frame/first/review-scope.json)를 수정 전 기록했습니다. 작성자 자신이 만든 평가이며 독립·맹검·전문가 평가가 아닙니다.

첫 실행에서 7개 질문의 계약이 실패했습니다. 점검하면 좋을까요(p01), 돌아볼 부분(p03), 이용 안내의 수신·미독과 읽음(p07·p08), 앞 문장의 약속을 이어받는 합의(p12), 내용이 없는 대안(p15), 쉼표로 연결한 성찰·감정 요청(p20)입니다. 원본의 실패와 전체 출력은 변경하지 않습니다. 이 검토 이후 이 질문들은 알려진 회귀 자료입니다. [수정 후 실제 회귀 출력](../test-results/request-frame/regression/review.html)을 구별합니다.

수정은 정중한 종결 표현과 실제 예측의 구분, 관형형 작업 결과물, 복합 명사로 된 전달 내용, 인접 문장의 생략된 대상, 감정의 명사형, 연결된 요청의 범위에 적용합니다. 질문 번호와 완성된 예문은 해석 소스에 넣지 않습니다. 받아 둔 내용을 아직 읽지 않은 경우에는 먼저 확인할 순서를 보존합니다. 실제 약의 양·금융 자산을 바꾸는 요청은 배경의 문서 편집으로 우회하지 않습니다.

## 보존한 개발 실패

[개발 폴더](../test-results/request-frame/development/)에는 초기 객체 오인, 배경 자료 우선, 명사 결과물 누락, 같은 요청 중복 제거, 실제 추가 상황 화면의 실패, 선행 안내와 새 작업 혼동, 필요한 자료를 완성된 문서로 읽는 오류, 기존 미독 안내 회귀를 남겼습니다. 문장 검토에서 발견한 개인 동기를 발신 문장으로 답한 오류와 충분한 감정 문맥에 추가 설명을 요구한 오류도 실제 출력·소스 패치와 함께 보존합니다. 중간 실패의 자동 통과율을 최종 품질로 사용하지 않습니다.

[기존 문장 일치 검사의 불일치](../test-results/request-frame/development/initial-legacy-wording-contract-disagreement.json)와 [신청 조건을 자격으로 좁힌 실제 항목 누락](../test-results/request-frame/development/initial-requirements-breadth-failure.json)을 함께 남깁니다. 단순한 표현 변경 외에 시간·비용·변경 조건이 빠지는 경우도 있어, 자격·요건이 명시된 경우에만 자격 안내를 쓰고 일반 조건은 기존의 필수 확인 본문을 재사용합니다. 기존 문장 보존 검사는 유지했습니다. 이 보완 뒤의 같은 최종 HTML에서 전체 필수 검사 명령을 독립된 세 그룹으로 다시 실행한 기록을 사용합니다. 최초 중간 후보의 전체 실행이 한 번에 성공했다고 표시하지 않습니다.

[생략된 조건의 후속 점검 오류](../test-results/request-frame/development/initial-omitted-requirements-regression.json)는 앞 문장의 명시적 조건을 이어받지 못해 일반 점검으로 답하던 실제 실패입니다. 기존의 선행 문서·관찰·근거 연결에 요건도 포함하고, 별개 작업의 명시적 대상은 유지하도록 했습니다. 저축·시설 이용·강좌 등록처럼 다른 분야의 같은 문장 구조도 확인합니다. [UI 임시 입력의 검사 불일치](../test-results/request-frame/development/initial-ui-context-fixture-disagreement.json)는 별도로 보존합니다. 문맥 없는 임시 질문의 기존 읽기 무효화 검사는 유지하며, 8종 배열 조작은 실제 일상 질문으로 실행합니다. 모호한 질문의 추가 상황 입력 경로는 전용 UI 검사에서 확인합니다.

전체 기술 검사를 통과한 중간 후보에서도 [구체적인 기존 조언을 잃은 여섯 실제 문장](../test-results/request-frame/development/initial-specialist-method-regressions.json)을 읽고 찾았습니다. 대상·결과물을 더 밝혀 주지 못하는 일반 점검 분류는 적용하지 않으며, 기존 표현 편집 방법은 유지하고 새 축약 안내는 명시적인 축약 요청에 적용합니다. 앱 동작 재현, 질문과 답변의 대조, 지급일·완료 기록 확인, 자기비난 표현의 구분 등 기존의 구체적 방법이 실제 출력에서 복구됐는지 확인했습니다. [27개 변경 핵심 문장과 여섯 복구 대조군](../test-results/editorial/v90-review.json)은 중간 출력·최종 출력·직접 읽은 범위를 함께 보존합니다. 복구한 답변이 전문가 수준이라는 뜻은 아닙니다.

임상 설명 축약은 증상·시작 시점·경과 등 실제 정보를 남기고 반복을 줄이는 범위입니다. [NIH/NIA의 진료 대화 안내, 11쪽](https://order.nia.nih.gov/sites/default/files/2021-06/talking-with-your-doctor.pdf)의 짧고 정확한 설명 원칙을 참고했습니다. 진단·약의 양·치료 여부를 카드로 결정하지 않습니다.

## 남은 품질 한계

28개 개발 질문과 20개 첫 평가의 다섯 장 배열 핵심 답변을 직접 읽었습니다. 상세 카드 보고서와 다른 모든 배열을 전부 사람이 다시 읽었다는 뜻은 아닙니다. 첫 평가에서 자동 계약이 통과한 답변에도 분야별 구체성 부족, 약한 사건·소유 연결, 반복되는 일반 조언과 카드 적용이 남았습니다. 낭독회와 녹음, 면접 질문, 안내 설명 등 실제 분야의 세부 맥락을 충분히 다루지 못합니다. 카드 조합을 한두 주제로 연결하는 문장이 길고 일반적일 수 있습니다.

검증 자료에는 자동 계약과 문장 검토 범위를 따로 남깁니다. 전체 기술 검사, 기존 회귀, 스트레스 출력, 원본 이미지, 매트, 오프라인·기기별 전체 보고서 일치는 [v90 검증 기록](../test-results/v90-validation.json)에 묶습니다. 이 결과는 전문 해석가 동등성이나 모든 질문에 대한 일반화 성능을 증명하지 않습니다. 무료·오프라인·외부 기기의 핵심 경로를 유지하며 전문가 목표와 후속 번역은 아직 완료되지 않았습니다.

main 병합 `970cf37cbef6fcebdb250270d6fa93457e54e66b`의 Pages 실행 `41176097831`이 성공한 뒤 실제 공개 주소를 Chrome 156.0.8078.76에서 검사했습니다. [공개 앱](../test-results/public-90-check.json)과 [진단 페이지](../test-results/public-device-90-check.json)의 336개 전체 해석이 로컬 기준과 일치하고 오프라인에서 원본 78장이 표시됐습니다. [UI 실행](../test-results/public-flow-90-check.json)은 두 격리 프로필에서 18개 선택·공개·내보내기·저장·기록 재열기 흐름과 새 오프라인 탭의 기록 유지·추가 저장·재접속을 통과했습니다. 모바일은 390×844 표준 화면·터치 에뮬레이션이며 실제 Android 조작·비행기 모드로 표시하지 않습니다. 합성 자료만 공개하고 개인 전화 진단·UA·기록 ID는 제외했습니다.
