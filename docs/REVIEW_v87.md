# v87 · 카드 관점을 실제 요청에 적용

핵심 답변이 실천 방법 뒤에 카드의 주제만 덧붙이고 끝나는 문제를 보완합니다. 카드의 ID·정역방향·배열 자리를 유지하면서 기존 세부 관점과 카드 간 관계를 요청한 설명·준비·수정·분담·마무리·감정 대처에 연결합니다. 원본 RWS 78장과 무료 오프라인 실행을 유지하며 유료 API·호스팅·PC 전용 서버를 추가하지 않습니다.

## 변화와 범위

실천 방법과 카드 해석을 문단으로 나눕니다. 이전의 구체적인 방법을 카드 문장으로 덮어쓰지 않고, 같은 카드가 다른 요청에 다시 쓰일 때는 이름과 관점을 반복 소개하는 대신 그 요청에 적용할 차이를 설명합니다. 제약·이후 흐름·이미 진행된 외부 절차의 자리를 사용자의 현재 사실이나 확정 결과로 바꾸지 않습니다. 건강·금전 등 보호된 해석에는 이 새 카드 처방을 추가하지 않습니다.

핵심 답변의 관점 라벨은 기존 `ARC81_PROFILES`와 `ARC81_MOTIFS`의 편집된 세부 관점입니다. 전통 의미의 직역이나 전문가의 검증을 받은 정답이라고 부르지 않습니다. [Waite 원전 Part III](https://en.wikisource.org/wiki/The_Pictorial_Key_to_the_Tarot/Part_3)의 §4도 배열의 순서와 위치에 따른 의미의 변화를 설명합니다. 이 참고가 전체 엔진을 원전대로 구현했다거나 해석의 타당성을 입증한다는 뜻은 아닙니다. 상세 근거에 남아 있는 좁고 강한 카드 표현도 계속 개선해야 합니다.

[개발 질문 12개 × 배열 8종의 실제 출력](../test-results/lens/development/review.html)과 [78장 × 정역방향 × 10개 작업의 1,560개 출력](../test-results/lens/development/matrix.jsonl.gz)을 남깁니다. 1,560개는 열 가지 알려진 표현의 카드 변형이며 서로 다른 질문 1,560개나 전문성 점수가 아닙니다. 작성자가 읽은 범위는 별도 `review-scope.json`에 기록합니다. 개발 중 이미 정한 계획의 실행 요청을 결정을 재고하는 질문으로 바꾸던 오류도 발견해 보완했습니다.

## 첫 평가와 이후 수정

후보 `39d81a9`의 HTML 해시 `d79a5aef2e627735296eb8beb69c8cd9ec4fcf098041c1f98cd24ce54bfba3e0`을 고정했습니다. 이후 `94621c5`에서 새 질문 20개를 작성하고 같은 질문·카드·방향·배열로 v86과 후보를 각각 160회 실행했습니다. 구현을 아는 작성자의 진단이며 독립 전문가나 완전한 블라인드 평가가 아닙니다.

[첫 실제 출력](../test-results/lens/first/review.html)과 실패를 `394ded7`에서 수정 전에 보존했습니다. 원본 출력 SHA-256은 `d7263373aed6f8bcd5e4c9fb38dbb6df1b1db0e71f32366b2e7a9a6b40dc2855`입니다. 첫 자동 계약은 128/160개만 통과했습니다. 네 질문에서 설명 목적·‘어디를 고치는 게 좋은지’·첫 실행·긴 복합 요청을 놓쳤습니다.

20개 다섯 장 배열의 핵심 답변을 직접 읽으니 자동 검사 밖의 실패도 있었습니다. 확인한 인쇄 연도/미확인 축척의 상태를 뒤집어도 같은 답변이 나왔고, 비교 요청이 빠졌으며, 작은따옴표 안의 잘못된 복약 문구에 내용 검토를 붙이지 못했습니다. 전망 질문의 조언은 낭독 자신감과 어긋났고, 두 문장 요청도 지키지 않았습니다. 첫 출력·요약은 덮어쓰지 않습니다.

이를 보고 공통 인용문 처리를 추가했습니다. 여섯 종류의 균형 잡힌 인용을 마스킹할 때 원문 위치를 유지하고, 사실·주체·수치·내용 검토가 같은 인용 범위를 사용합니다. 이름의 아포스트로피를 인용으로 만들지 않습니다. 목적 뒤의 일반적인 순서/범위 질문, 의문어의 조사, 주된 행동과 그 결과의 구분, 쉼표로 이어진 공동 요청과 명사형 비교도 보완했습니다. 명확한 자료 주제 뒤에 확인 사실만 이어지면 설명의 생략된 대상을 잇고, 새 주제가 등장하면 무조건 이어받지 않습니다.

[수정 뒤 출력](../test-results/lens/regression/review.html)은 알려진 회귀 자료입니다. 미사용 평가나 일반화 성능 점수로 다시 세지 않습니다. 실천 보존 계약도 단순히 작업 종류가 같은지에서 대상·참여자·완료·내용 검토 조건까지 같은지로 구체화했습니다. 잘못된 개인 선택 조언을 자료 설명으로 고친 경우에는 과거의 잘못된 문장을 남기도록 요구하지 않습니다. 이전 첫 계약과 실제 실패는 그대로 보존합니다.

## 기기 검증

[기기 확인 페이지](../device-check.html)는 배포 자료와 동일한 입력·실행 함수의 지문을 확인하고, 144개 조합의 전체 답변과 원본 78장의 표시를 해당 브라우저에서 검사합니다. 저장한 리딩을 결과에 넣거나 결과를 서버로 전송하지 않으며, 사용자가 결과를 복사할 수 있습니다. 오래된 앱·다른 답변 지문·누락된 검사 파일을 성공으로 표시하지 않는 경로도 검사합니다.

사용자는 실제 확인 대상으로 Android 휴대전화의 Chrome을 지정했습니다. 아직 실제 휴대전화에서 실행한 결과를 받았다는 뜻은 아닙니다. 자동 검사는 Chromium 화면·터치 프로필이며 실제 Android·Safari와 구별합니다. 기기 확인 페이지의 결과도 물리적 기기, 실제 카드 선택·저장·설치·비행기 모드 재접속까지 자동으로 증명하지 않습니다. 공개 배포 뒤 사용자의 실제 실행 결과와 수동 확인이 필요합니다.

## 검증과 남은 실패

기존 320개 질문과 비교해 바뀐 핵심 답변 52개를 직접 읽었습니다. 기본 실천 방법과 사실 메타데이터는 v86과 같았지만, 일부 감정 질문에서 예전 조언 카드의 단순 문장이 새 현재 카드 관점과 함께 남아 중복됐습니다. 실제 출력 9개를 `v87-initial-footer-findings.json`에 보존한 뒤, 답변 안에 실제로 쓰였던 카드 문장을 찾아 대체하고 핵심 답변의 카드 참조를 새 문장의 자리와 맞췄습니다. 질문에 상실 사실이 없는 세 답변의 상실 관점도 조건부 표현으로 고쳤습니다. 최종 변경 문장의 재검토와 비교 범위는 별도 `editorial/v87-review.json`에 기록합니다.

최종 회귀의 핵심 답변 20개와 개발 답변 12개를 모두 다시 읽었고, 다른 배열 네 출력과 두 질문의 다섯 장 상세 근거도 추가 확인했습니다. 짧은 배열의 복합 요청에서는 조건부 표현이 연달아 반복되는 어색함도 남아 있습니다. 모든 상세 출력이나 행렬 1,560개를 사람이 읽었다는 뜻은 아닙니다.

최종 기술·회귀 결과는 [검사 묶음](../test-results/v87-validation.json)에 연결합니다. 기존 320개 질문·1,024개 스트레스 조합·72개 통합 출력과 과거 평가 자료는 모두 알려진 회귀입니다. 자동 검사·개발 행렬·일치 검사를 의미 품질이나 전문 해석가 동등성의 근거로 바꾸지 않습니다.

최종 앱 SHA-256은 `d7be73ee32f84493a35d72401ee4ffa06cc03d7aa3d452070f20c0d4af427052`입니다. [CRLF 소스 재빌드](../test-results/build-repro-v87.json)에서 앱·서비스 워커·배포 정보가 정확히 같았고, 커밋 `10340bf`의 [별도 Git 체크아웃](../test-results/checkout-repro-v87.json)에서도 공개 파일·진단 파일·첫 실패 원본 등 14개 파일이 커밋 바이트와 같았습니다. 이는 재현성 검사이며 의미 품질 점수가 아닙니다.

main `6e3d09d` 배포 성공 뒤 [공개 앱](../test-results/public-87-check.json)과 [공개 진단 페이지](../test-results/public-device-87-check.json)도 실제 HTTPS에서 검사했습니다. 같은 최종 앱 바이트, 두 새 프로필의 오프라인 144개 전체 출력, 원본 78장과 진단 페이지의 실행을 확인했습니다. 물리적 Android Chrome의 사용자 실행 결과는 아직 수신 전입니다.

추가 메타데이터 검토에서 4번 질문의 명시적인 대기 부정을 내부 대기 상태로 잘못 읽는 문제도 확인했습니다. 보이는 답변은 마음 돌보기이지만 내부 사실 처리는 틀렸습니다. 18번의 이미 받은 답변도 명시적 수신 사건으로 충분히 표현하지 못합니다. 7번 전망 조언의 대상 적합성, 17번 금전 조건의 깊이와 메타데이터, 20번의 두 문장 형식, 반복 지시문과 분야별 해석의 깊이도 남아 있습니다. 전문가 수준과 전체 기기 목표는 아직 미완료이며, 목표를 완수한 뒤 번역한다는 순서를 유지합니다.
