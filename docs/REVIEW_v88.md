# v88 검토 기록

기다림의 명시적인 부정, 이미 받은 회신의 관형절, 미독과 발신을 구분합니다. 실제 받은 내용과 이어지는 요청에만 수신 맥락을 적용합니다. 입력의 준비 여부도 같은 질문 분석기로 판단해 예전 분야 선택창과의 충돌을 없앴습니다. 원본 RWS 78장과 무료·기기 내 실행 원칙을 유지합니다.

## 자료와 직접 읽은 범위

- 개발 질문 20개 × 8배열의 v87/v88 실제 보고서 160쌍: [전체 출력](../test-results/event-state/development/review.html), [직접 검토 범위](../test-results/event-state/development/review-scope.json). 다섯 장 배열의 핵심 답변 20개를 모두 읽었습니다. 313개 문법·변형 사례와 13개 맥락·미독 단언은 알려진 개발 계약이며 새로운 사용자 질문 326개로 세지 않습니다.
- 후보 구현 커밋 `83cd30a` 뒤 만든 새 질문 20개 × 8배열: [첫 출력](../test-results/event-state/first/review.html), [검토 범위와 실패](../test-results/event-state/first/review-scope.json). 첫 원본 SHA-256은 `91bdf1a5c929defdceb393b827563b13dcb2f3200089b23b8cbdeb921369cce4`입니다. 다섯 장 배열의 핵심 답변 20개를 모두 읽었습니다. 작성자 자체 평가이며 독립·맹검·전문가 평가가 아닙니다. 이후에는 알려진 자료로 분류합니다.
- 기존 편집 질문 320개 중 달라진 핵심 답변 2개(148·268)와 사실 표지 3개(36·282·284)를 직접 비교했습니다. 나머지 핵심 답변 318개는 v87과 동일합니다. [검토 기록](../test-results/editorial/v88-review.json).

첫 출력의 지정된 사실 계약은 160/160이지만 의미 품질의 통과율이 아닙니다. 미독 회신을 먼저 읽도록 연결하지 못한 e01, 질문을 준비하려는 목적을 놓친 e07, 이미 읽은 내용과 맞지 않는 조언을 붙인 e09, 다른 사람의 상황을 사용자의 일에 끌어온 e11 등이 남았습니다. e03·e06·e13·e16은 요청한 실천에 비해 포괄적인 답변입니다. 첫 출력과 메모를 보존합니다.

과거 맥락 회귀 검사에서는 관형절의 ‘는’을 주체 조사로 읽은 실제 오류도 발견했습니다. 수정 전 432개 출력은 `test-results/event-state/development/context-failure-826506edddc7.jsonl.gz`에 보존합니다. 생산적인 관형절 어미를 주체와 구별하도록 보완했습니다. 별도로, ‘대답을 기다린다’는 서술에 미수신을 요구하던 과거 공통 기대값 한 항목을 수신 미확정으로 바로잡고 발신 정·부정과 명시적인 미수신 단언은 강화했습니다. [계약 수정 사유](../test-results/event-state/development/property-contract-corrections.json)를 기록하며 최초 자료는 바꾸지 않습니다.

## 남은 한계

개발 d11은 ‘해설사’ 안의 ‘설사’를 기존 분야 분류기가 증상으로 오인합니다. d15는 다른 사람의 대기와 별개인 질문을 관계 문제로 답하고, d16·d17은 문장 편집·가정 질문을 충분히 이해하지 못합니다. 사실·주체가 맞아도 요청의 의미가 틀릴 수 있습니다. 기존 l07의 전망 조언, l17의 금융 맥락 깊이, l20의 두 문장 형식도 해결되지 않았습니다. 반복적인 일반 조언과 약한 카드 통합도 남아 있습니다. 추가로 [발신·미발신 질문 6개를 직접 읽은 기록](../test-results/event-state/development/context-review.json)에서는 첫 말 걸기 요청에 구체적인 시작이 부족하고, 재발송 충동을 다루는 질문에 비교·자기 가치 조언을 붙이는 한계를 확인했습니다.

무료 브라우저 형태소 분석 경로를 검토했습니다. [Garu 공식 코드](https://github.com/ongjin/garu)와 [Kiwi 공식 WASM 문서](https://github.com/bab2min/Kiwi/tree/main/bindings/wasm)를 확인했고, 로컬 합성 질문으로 Garu 0.11.0 시제품이 ‘해설사’, ‘설사’, ‘식후구토’를 구별하는 것은 관찰했습니다. 이는 제품 검증이 아닙니다. 제품에는 모델·의존성을 추가하지 않았습니다. 비동기 초기화·오프라인 포함·라이선스 고지·외부 기기에서의 동일 동작을 확인한 뒤 적용 여부를 판단해야 합니다. 추가로 [8개 합성 문장의 브라우저 시제품 기록](../test-results/event-state/development/morphology-prototype.json)에서 데스크톱과 표준 모바일 에뮬레이션의 토큰 결과가 같았습니다. 실제 기기·처음부터의 오프라인 실행·제품 통합은 검사하지 않았습니다. 여덟 문장의 시제품 성공으로 일반화 성능을 주장하지 않습니다.

## 실행 범위

로컬 모바일 터치 에뮬레이션에서 수신·미독 질문의 선택→공개→내보내기→저장→기록 열기 4개 흐름과 입력 부족 확인창을 직접 실행했습니다. [UI 기록](../test-results/event-state/ui-summary.json). 원본 카드·매트·기기 비교·오프라인과 전체 회귀 검사는 최종 빌드의 검증 파일에 별도 기록합니다.

최종 HTML SHA-256은 `d5cdb74be01768a59a240b9f18645d468690d8faba33fd8f33d49cec1ed2ab88`입니다. [최종 검증](../test-results/v88-validation.json)은 전체 테스트와 과거 704개 회귀, 1,024개 스트레스 출력, 원본 78장, 매트 32개, 3개 프로필×192개 전체 답변 일치, 오프라인과 CRLF 빌드 재현을 통과했습니다. 5개 최초 출력 원본의 해시도 보존했습니다. 이는 기술·알려진 회귀 검사이며 의미 품질이나 전문가 점수가 아닙니다.

병합 후 [공개 주소 검사](../test-results/public-88-check.json), [진단 페이지](../test-results/public-device-88-check.json), [Chrome UI 18개 흐름](../test-results/public-flow-88-check.json)도 통과했습니다. 실제 HTTPS의 같은 파일로 오프라인 전체 답변 192개와 원본 78장을 확인하고, 8종 배열의 선택·공개·저장·기록 보기 및 오프라인 새 저장·재접속을 실행했습니다. 미독과 이미 받은 회신 질문의 실제 입력창 경로도 통과했습니다. 모바일은 표준 터치 에뮬레이션입니다.

실제 휴대전화의 UI·비행기 모드를 원격으로 조작한 검사는 아닙니다. 현재 연결된 기기 제어 경로가 없어 이 범위는 확인되지 않았습니다. v87 진단 실행과 v88의 새 검사도 구별합니다. 개인 기기 진단 원문은 공개 저장소에 포함하지 않습니다. 자동 검사와 자체 검토만으로 전문가 동등성이나 모든 질문의 이해를 달성했다고 판단하지 않습니다.
