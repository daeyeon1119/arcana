# 외부 기기에서의 동일한 동작

v88은 수신·미독·발신 주체와 기다림 부정 6개 질문을 추가해 3개 화면 프로필에서 각각 192개 전체 보고서를 비교합니다. [최종 로컬 검사](../test-results/portable-summary.json)는 같은 답변 지문, 원본 78장, 오프라인 새 탭·기록 이동·업데이트 실패와 적용을 통과했습니다. 실제 Android의 터치·설치·비행기 모드는 현재 기기 제어 연결이 없어 별도로 미확인 상태입니다. v87에서 받은 기기 진단과 v88의 검사 결과를 섞지 않습니다.

main `20b4b70` 병합과 Pages 실행 `41004353765` 성공 후 [실제 공개 앱 검사 7개](../test-results/public-88-check.json)와 [공개 진단 페이지 실행](../test-results/public-device-88-check.json)을 통과했습니다. 앱 SHA-256은 `d5cdb74be01768a59a240b9f18645d468690d8faba33fd8f33d49cec1ed2ab88`로 최종 로컬 검사본과 같습니다. 공개 주소에서도 프로필당 192개 전체 답변과 원본 78장을 확인했습니다.

[공개 Google Chrome UI 검사](../test-results/public-flow-88-check.json)는 Windows Chrome `156.0.8078.76`의 데스크톱 마우스·표준 390px 터치 에뮬레이션에서 8종 배열의 선택·공개·저장·기록 열기와 오프라인 새 리딩을 포함한 18개 흐름을 실행했습니다. 이번 입력 확인창 오류가 있었던 미독·수신 질문도 포함합니다. 각 프로필에서 오프라인 새 탭의 기존 기록 8개와 새 리딩을 저장한 뒤 재접속한 기록 9개를 확인했습니다. 합성 테스트 프로필만 사용했으며 UA·기록 ID를 뺀 파생 기록을 공개합니다. 물리적 휴대전화의 비행기 모드 검사로 세지 않습니다.

사용자는 개인 PC뿐 아니라 외부 기기에서도 같은 수준으로 앱이 작동할 것을 요구했습니다. 무료 로컬 모델이 이 PC에서 답변을 만들었다는 사실만으로 제품 요구를 충족했다고 판단하지 않습니다. 정식 앱은 [공개 주소](https://daeyeon1119.github.io/arcana/)의 같은 파일을 각 기기에서 실행합니다. 같은 기기 내 JavaScript 해석을 사용하며 개인 PC의 서버나 유료 API를 사용하지 않습니다.

## 이번 구현

- 원본 RWS 78장과 해석 코드를 한 HTML에 유지했습니다. 모바일 전용으로 원본이나 해석 단계를 생략하지 않습니다.
- HTTPS 웹 앱의 서비스 워커가 앱·설치 정보·아이콘만 저장합니다. 질문·리딩 기록을 서버로 보내거나 캐시 URL에 넣지 않습니다.
- 앱의 SHA-256과 배포 파일 묶음의 지문을 빌드 시 고정합니다. 오프라인 저장 전 실제 내려받은 HTML 해시를 검사하고, 모두 저장한 뒤에만 설치를 완료합니다. 저장 실패 시 기존 배포 캐시는 유지합니다.
- 앱 HTML·PNG는 정확한 바이트를 기준으로 삼고, 배포 지문에 들어가는 manifest·SVG 텍스트는 LF로 정규화합니다. Git 체크아웃의 Windows CRLF 변환만으로 서로 다른 배포가 생기지 않도록 합니다. 공개 배포 파일의 줄바꿈도 `.gitattributes`에 고정합니다.
- 업데이트는 현재 화면을 자동으로 새로고침하지 않습니다. 사용자가 적용을 고르고 진행 중인 리딩 초기화 안내를 확인해야 반영합니다. 기록용 localStorage는 캐시 정리 대상에 포함하지 않습니다.
- URL 하위 경로에 배포할 수 있으며, HTML 파일을 직접 여는 기존 오프라인 사용도 유지합니다.
- 읽기 엔진의 버전과 앱 버전을 구분합니다. v82.1.0은 기기·배포 기능의 변경이며 해석 수준이 올라갔다는 표시는 아닙니다.

[MDN 서비스 워커 문서](https://developer.mozilla.org/en-US/docs/Web/API/Service_Worker_API/Using_Service_Workers)의 설치·활성화와 [Chrome 수명 주기 설명](https://developer.chrome.com/docs/workbox/service-worker-lifecycle)에 따라 설치 완료와 새 버전의 적용을 구분합니다. 서비스 워커가 차단되면 온라인 리딩은 유지하고 오프라인 준비 완료를 표시하지 않습니다. 저장 공간 부족·사이트 데이터 삭제·브라우저의 저장소 회수로 오프라인 파일이 사라질 수 있습니다. 상태 확인과 재시도를 제공하며 영구 보관을 보장하지 않습니다.

## 검증 기준과 한계

`scripts/portable.cjs`는 실제 브라우저의 Cache Storage와 Service Worker를 사용합니다. 테스트 서버를 차단한 뒤 새 탭을 열고 같은 해석을 다시 만듭니다. 서로 다른 화면·픽셀 비율·언어·시간대에서 같은 입력의 전체 보고서를 비교합니다. v85 검사는 자동 설정 48개에 복합 요청·수동 분야·초점 32개를 더한 80개 조합입니다. v86은 확인 상태·생략·수정 이유 질문 3개를 추가한 104개 조합입니다. 로컬과 공개 검사에서 같은 실행 함수·입력 지문을 확인합니다. 저장한 질문·카드의 JSON 백업을 격리된 다른 프로필로 옮깁니다. 의도적으로 해시가 틀린 배포를 주어 기존 오프라인 앱이 유지되는지, 적용 취소 때 진행 중인 리딩이 남는지, 업데이트 뒤 기록과 다른 앱 캐시가 보존되는지 확인합니다.

모바일 프로필은 같은 Chromium 엔진에서 Android·iPhone 화면과 터치를 흉내 냅니다. **실제 Android/iPhone이나 Safari에서 실행했다는 증거가 아닙니다.** 공개 HTTPS 주소의 새 프로필 실행도 별도로 확인합니다. 물리적 기기의 저장 용량·브라우저 정책·설치 메뉴 차이와 모든 기기의 호환성은 아직 검증하지 못했습니다.

해석의 일치는 입력·설정·버전이 같다는 조건 아래 확인합니다. 카드 추첨 결과가 다른 두 리딩의 문장이 같아야 한다는 의미는 아닙니다. 데이터 이동을 확인한 것은 자동 클라우드 동기화가 있다는 뜻도 아닙니다. 이 검사는 전문가 수준의 의미 품질 평가를 대체하지 않습니다.

```sh
python scripts/build.py
npm run test:portable
# GitHub Pages가 같은 버전을 배포한 뒤, 실제 인터넷 연결로 별도 실행
npm run verify:public
```

### 에이전트가 직접 실행한 공개 UI 검사

[공개 Chrome UI 실행 기록](../test-results/public-flow-87-check.json)은 Windows에 설치된 Google Chrome의 격리된 합성 프로필을 사용합니다. 기본 네 배열은 보이는 선택 버튼으로, 특수 네 배열은 실제 자동 추천 버튼으로 선택합니다. 데스크톱 마우스와 표준 390×844 터치 에뮬레이션에서 총 18개 선택·공개·저장·기록 보기 과정을 실행합니다. 각 프로필의 온라인 8개와 네트워크 차단 후 새 리딩 1개입니다. 같은 핵심 답변의 화면·내보내기·저장 기록 일치, 매트 폭·중복 이름 없음, 기존 8개 기록의 오프라인 새 탭 보존과 9번째 리딩 저장 후 재접속 보존을 확인합니다. 새 질문의 의미 품질 평가로 세지 않습니다.

개인 기기 UA·기기 식별값·사용자의 저장 기록·개인 화면은 공개 결과에 넣지 않습니다. 공개 JSON은 합성 질문·추첨·답변과 기능 검사 결과만 포함하며, 검사 프로필 UA와 기록 ID도 생략합니다. 브라우저 네트워크 차단은 실제 휴대전화의 비행기 모드와 구별합니다.

```sh
# 설치된 Google Chrome 실행 파일을 ARCANA_BROWSER로 지정한 뒤 별도 실행
node scripts/public-flow-check.cjs
```
