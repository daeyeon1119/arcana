# 과금 없는 의미 해석 경로 검증

사용자의 원칙은 **유료 서비스를 사용하지 않는 것**입니다. 유료 API·호스팅·구독·크레딧, 결제 수단을 연결한 무료 체험을 도입하지 않습니다. 현재 앱의 기본 리딩은 v82 오프라인 엔진이며 질문을 추론 서버로 보내지 않습니다.

추가 요구는 **외부 기기에서도 같은 수준으로 작동하는 것**입니다. 이 PC의 로컬 추론은 연구용 진단이며 정식 기능의 제공 경로로 채택하지 않았습니다. 모델의 실제 해석 품질과 함께 개인 PC의 상시 실행·대용량 설치에 의존하지 않는 외부 기기 제공 경로까지 검증해야 합니다. [공개 웹 앱과 기기 간 기준](DEVICE_PORTABILITY.md)을 따릅니다.

특정 예문의 예외를 늘리는 대신, 무료 공개 언어모델에 원문 질문과 실제 카드 근거를 직접 전달하는 경로를 검증합니다. 아직 이 경로를 앱의 기본 해석으로 활성화한 것은 아닙니다. 실행·형식 검사와 실제 문장 품질을 구분합니다.

[첫 실제 답변 검토 결론](../test-results/local-reader/REVIEW_FIRST.md): 서로 다른 질문 15개의 완성된 답변과 두 단계 후보의 개발 질문 1개를 읽었습니다. 첫 전송 실패·재시도를 분리했고, 단정·카드 뜻 반복·요청 미충족이 남아 두 후보 모두 기본 엔진에 채택하지 않았습니다. 외부 전문가 평가는 수행하지 않았습니다.

## 고정한 입력과 출력

`src/local-reader-core.js`는 DOM·카드 추첨·모델 제공자와 독립된 계약입니다. 첫 새 상황을 작성하기 전 커밋 `b3031cb`에 프롬프트와 계약을 고정했습니다.

- 모델에 원문 질문, 직접 선택한 초점·분야, 카드 ID·이름·정역방향·자리·자리 설명·전통 의미를 전달합니다. 기본 엔진이 추측한 분야·사실 상태와 기존 답변을 정답처럼 전달하지 않습니다.
- 요청의 원문 인용과 직접 답변, 여러 카드의 통합 해석, 모든 카드의 위치별 관점, 실천과 미확인 정보를 구분해 받습니다.
- JSON 구조, 인용이 실제 원문의 연속 구간인지, 참조한 카드가 실제 배열에 있는지, 카드별 설명이 빠지지 않았는지 검사합니다. 카드 이름과 방향의 표시는 입력에서 가져옵니다.
- **이 검사는 의미의 정확성이나 카드 해석의 타당성을 증명하지 않습니다.** ‘아직 답을 못 받음’에 ‘받은 답을 적어 보세요’라고 쓴 잘못된 문장도 형식상 통과할 수 있다는 개발 검사를 명시했습니다.

개발용 계약 검사 28항목은 `node tests/local-reader-core.cjs`로 재현합니다. 실제 사용자 질문 28개를 검토한 결과라는 뜻은 아닙니다.

## 실제 브라우저 실행에서 얻은 제약

MLC의 공식 모델 등록과 [WebLLM 사용법](https://webllm.mlc.ai/docs/user/basic_usage.html)을 확인하고 `@mlc-ai/web-llm@0.2.86`의 `Qwen3-4B-q4f16_1-MLC`를 실행했습니다. 이 Windows 기기는 Intel Core i5-1035G4, Iris Plus, 약 16GB RAM입니다.

임시 브라우저 프로필은 모델 가중치 약 774MB를 받은 뒤 저장 용량 초과로 실패했습니다. 안정된 출처와 영구 진단 프로필로 다시 실행해 약 2.16GB의 가중치를 받았습니다. 짧은 진료 대화 준비 질문의 답변은 43토큰이었고, 생성에 약 **145.4초**가 걸렸습니다. 결과와 추론 속도는 `test-results/local-reader/probe.json`에 있습니다. 전체 카드 리딩의 품질을 검증한 결과가 아닙니다.

이 지연을 이유로 브라우저 모델을 기본 해석으로 켜지 않았습니다. 기본 앱의 카드 추첨·원본 이미지·오프라인 해석에는 영향을 주지 않습니다.

## 설치 없는 CPU 실행 진단

[Qwen 공식 GGUF](https://huggingface.co/Qwen/Qwen3-4B-GGUF)와 [llama.cpp 공식 Windows CPU 빌드](https://github.com/ggml-org/llama.cpp/releases/tag/b11900)를 작업 폴더의 `.cache/local-reader/`에만 둡니다. 다운로드는 약 2.50GB의 모델과 약 24.2MB의 실행 파일 묶음입니다. 출처·바이트 수·SHA-256·라이선스는 `scripts/local-reader-resources.json`에 고정했습니다. 시스템에 설치하거나 서비스를 등록하지 않습니다.

```powershell
python scripts/prepare-local-reader.py
$env:ARCANA_MODEL_DIAGNOSTIC='1'
node scripts/local-reader-native.cjs
python scripts/local_reader_report.py
```

Playwright와 Chromium/Edge가 필요합니다. 기존 브라우저를 쓰려면 README의 `ARCANA_BROWSER`·`ARCANA_NODE_MODULES` 설정을 사용합니다. 모델 진단은 선택적으로 실행하는 별도 명령이며 기본 `npm test`에서 대용량 모델을 자동 다운로드하거나 실행하지 않습니다.

진단은 이 기기의 `127.0.0.1` 임시 포트에서만 추론하고, 모델 서버를 시작한 프로세스가 종료할 때 함께 닫습니다. 질문·카드를 외부 추론 서버로 전송하지 않습니다. 모델 파일의 최초 다운로드에는 인터넷이 필요합니다. 실제 답변·질문·카드는 검토·재현을 위해 저장소의 평가 파일에 남으므로 평가에는 개인 정보가 없는 작성 질문만 사용합니다.

`tests/local-reader-first.json`은 알려진 실패 질문 3개와 계약 고정 후 작성한 새 상황 12개입니다. [실제 출력 비교](../test-results/local-reader/native-first/review.html)에서 카드별 설명과 원본 JSON까지 볼 수 있습니다. 아직 실행하지 않은 항목은 출력이 없다고 표시하며, 검토하지 않은 항목을 품질 통과로 세지 않습니다. 최초 출력을 덮어쓰지 않습니다. 관찰 후 프롬프트를 바꾸면 다른 실행 폴더에서 평가하고 이후 같은 질문의 결과는 회귀 자료로 분류해야 합니다.

이 검증은 무료 경로의 실행 가능성과 실제 문장 품질을 판단하기 위한 단계입니다. 전문 해석가와의 독립 비교나 모든 새 질문에서의 성능을 입증한 것은 아닙니다.

## 질문을 먼저 읽는 다음 후보와 실행 장애

알려진 개발 질문 3개에서 카드 뜻을 그대로 반복하고 상징을 실제 상황처럼 쓰는 문제가 나타났습니다. 카드를 보지 않고 원문 요청·명시 상황·계획/부정/전언·미확인 정보를 먼저 정리하는 후보를 `c0fe7a8`에 고정했습니다. `src/local-reader-planner.js`의 개발 검사 16항목은 질문 분석이 카드 교체와 무관한 입력을 받는지, 원문 인용을 보존하는지 확인합니다. 이것도 분석의 의미적 정확성을 증명하지는 않습니다. 이 후보에 같은 진단 질문을 다시 쓰는 결과는 별도의 재사용 자료입니다.

두 평가를 같은 CPU 슬롯에서 겹쳐 실행하다 첫 실행의 `n04`가 약 304초 뒤 `fetch failed`로 끝났고, 서버를 소유한 실행이 종료되면서 두 단계 후보의 리딩도 받지 못했습니다. [실행 장애 기록](../test-results/local-reader/execution-interruption.json)과 [직전 로그](../test-results/local-reader/transport-interruption.log)를 보존합니다. Undici의 기본 헤더 대기 한도 300초와 일치하는 정황이지만 원래 오류의 내부 코드는 저장하지 않아 원인 추정으로 구분합니다. [공식 전송 문서](https://github.com/nodejs/undici/blob/main/docs/docs/api/Client.md)

외부 목적지·리다이렉트를 허용하지 않는 로컬 전용 전송을 추가하고, 긴 생성에 맞는 전체 대기 한도를 명시했습니다. 실제 로컬 테스트 서버의 전송·외부 주소 차단·시간 초과 등 6항목을 검증했습니다. 이후 실제 모델 평가는 순차 실행하고, 이미 저장된 첫 실패는 덮어쓰지 않습니다. 이런 실행 장애를 답변 품질 실패나 통과로 세지 않습니다.

[편집 목표 예시 6개](../test-results/local-reader/editorial-targets.json)는 실제 질문·카드에서 어떤 구체성과 사실 구분을 기대하는지 저자가 작성한 참고문입니다. 실제 모델 출력, 외부 전문가의 답변, 독립 정답이나 앱의 예문별 대체 답변이 아닙니다. 현재 프롬프트에도 이 참고문을 넣지 않았습니다.

## 출처를 가린 검토 도구

[검토 화면](../test-results/local-reader/native-first/blind-review.html)은 같은 질문·카드의 v82와 무료 모델의 실제 답변을 A/B로 섞어 보여 줍니다. 제목·엔진 표시는 숨기고 본문·실천·카드 근거는 실제 문장 그대로 사용합니다. 문체로 출처를 짐작할 수 있어 엄밀한 이중 맹검으로 주장하지 않습니다. 질문별 소스 키는 `blind-key.json`에 따로 보관합니다.

원본 RWS JPEG의 SHA-256을 확인한 뒤 파일 바이트 그대로 넣어, 보고서를 열 때 외부 이미지 서버를 사용하지 않습니다. 미실행·실행 실패는 삭제하지 않으며 평가할 수 없다고 표시합니다. 여섯 평가 축의 점수는 미리 채우지 않습니다. 검토자가 선택한 0점과 미평가는 구분하고, 질문·카드·두 답변의 해시에 묶어 이 브라우저에 저장하거나 JSON으로 내보낼 수 있습니다. 검토 내용은 외부로 전송하지 않습니다.

```powershell
python scripts/local_blind_review.py
npm run test:blind-review
```

타로 실무자라는 선택은 자기 신고이며, 작성자가 자체 검토한 것과 구분합니다. **현재 외부 전문가의 평가 결과는 없습니다.** 브라우저 동작 검사에서 넣는 값은 격리된 프로필의 명시적인 `TEST ONLY` 자료이며 평가 결과로 집계하거나 저장소에 올리지 않습니다.

## 두 번째 무료 후보와 새 평가 자료 분리

[Qwen3.5-9B](https://huggingface.co/Qwen/Qwen3.5-9B)의 Apache-2.0 공개 모델을 [bartowski의 고정 GGUF 파일](https://huggingface.co/bartowski/Qwen_Qwen3.5-9B-GGUF/tree/182be2fd6c7bc44887d88a91cb03ff009cc9f549)로 받았습니다. 모델은 약 6.17GB이며 고정 출처·리비전·바이트 수·SHA-256·샘플링 설정은 `scripts/local-reader-profiles.json`에 있습니다. 컨텍스트 4096, CPU 스레드 4개로 실행합니다. 기존 Qwen3-4B 설정과 첫 기록은 유지합니다.

```powershell
python scripts/prepare-local-reader.py --profile=qwen35-9b
$env:ARCANA_MODEL_DIAGNOSTIC='1'
node scripts/local-reader-native.cjs --profile=qwen35-9b --cases=d01,d02,d03 --run=development-v1
python scripts/local_reader_report.py --profile=qwen35-9b --run=development-v1
```

`--describe`를 붙이면 모델을 시작하지 않고 선택한 설정을 볼 수 있습니다. `--fixture=tests/파일.json`은 프로젝트의 테스트 폴더 내부 파일만 허용하며, 보고서도 같은 질문 파일과 고정 해시를 확인합니다. 알 수 없는 모델·옵션·카드 ID·중복 질문·출력 경로 이탈은 거부합니다. 기본 `npm test`는 모델을 다운로드하거나 실행하지 않습니다.

[실제 검토 결과](../test-results/local-reader/REVIEW_QWEN35.md)는 개발 질문 3개의 답변과 두 단계 후보 1개입니다. 여전히 질문과 다른 조언, 없는 사실·인과관계가 나와 기본 해석에 채택하지 않았습니다. 실행은 약 3~5분 걸렸고 메모리 여유도 작았습니다. 모델 크기를 키운 것만으로 해석 품질을 해결했다는 결론을 내리지 않습니다.

후보 설정을 고정한 다음 별도 질문 14개를 첫 답변 수신 전에 커밋했습니다. 이 질문들은 아직 실행하지 않았으며 평가 성적으로 세지 않습니다. 개발 질문에서 드러난 실패를 수정한 후보를 다시 시험할 때는 후보 설정과 첫 출력을 별도로 보존해야 합니다.
