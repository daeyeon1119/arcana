# v85 · 요청에 맞는 배열과 카드 연결

비교가 아닌 질문에도 비교 배열의 A/B 해석이 핵심 답변에 붙던 문제를 보완합니다. 실제로 비교를 요청했는지와 수동 초점을 확인하고, 각 요청에 맞는 카드 관계를 선택합니다. 유료 서비스·API·특정 PC의 모델을 추가하지 않습니다. 원본 RWS 78장과 오프라인 실행은 유지합니다. 전문 해석가 수준에 도달했다는 뜻은 아닙니다.

## 구조 개선

배열의 물리적 위치와 질문에서 그 자리에 배정할 대상을 구별합니다. 비교 요청이 없으면 A/B를 특정 선택지의 결과로 사용하지 않으며, 화면·상세 근거·내보내기에 미배정 범위를 표시합니다. 카드나 배열을 임의로 다시 뽑지 않습니다. 실제 비교 요청은 A/B 위치를 유지하고, 비교와 실천이 함께 있으면 실천 답변에 두 선택지가 함께 작용한다고 해석하지 않습니다.

단일 카드 관점과 카드 관계에서도 실제로 등장한 참여자를 확인합니다. 참여자가 불명확한 질문에 상대의 선택·동의·관계 회복을 전제로 붙이지 않고, 기대와 실제 경험·감당할 범위·활용할 자원으로 읽을 수 있게 했습니다. 다른 사람의 참여가 확인되는 경우에는 관련 관점을 유지합니다. 이는 제한된 문법에 의존하는 문맥 처리이며, 등장인물을 완전히 이해한다는 의미는 아닙니다.

요청 문장을 접속된 술어 단위로 나눕니다. 뒤의 공손한 요청 표현을 함께 사용하는 ‘비교하고 마칠 기준도…’, ‘마음을 돌보고 연습을 바꾸려면…’에서 마지막 작업만 남기지 않도록 했습니다. 마무리 기준·다듬기·명사화된 질문과 분담할 확인 범위도 처리합니다. 기존 병렬 명사 요청과 사건·주체·부정·완료 여부 검사는 유지합니다. 보이는 조언을 교체한 뒤 작업 메타데이터가 과거 작업 종류를 가리키던 문제도 고쳤습니다.

저장 기록의 엔진 버전은 과거 리스너의 고정 숫자보다 최종 빌드 메타데이터를 따릅니다. 로컬·공개 배포의 기기 일치 검사는 공통 실행 함수를 사용하고 질문·카드·방향·배열뿐 아니라 분야·초점 설정도 입력에 포함합니다.

## 첫 평가와 실제 실패

기존 질문 12개 × 배열 8종의 개발 출력과 360px 실제 화면 경로를 확인한 뒤 후보 `624494e`를 고정했습니다. HTML 해시는 `634ced37ea7a81db5489f92596f290d401030c2223304e794d2f7f67da67f73f`입니다. 이후 `f91bb42`에서 새 질문 16개를 작성하고 같은 카드·방향·배열·수동 설정으로 v84와 후보를 각각 128회 실행했습니다.

[첫 실제 출력](../test-results/alignment/first/review.html), [16개 비교 배열 핵심 답변의 검토 범위](../test-results/alignment/first/review-scope.json), [질문별 실패](../test-results/alignment/first/review-notes.json)를 보존합니다. 첫 출력 파일 SHA-256은 `fc08edfb43a068b1b1c724bd19cec322a096cd6686beef86181a1637d2a827a6`입니다. 작성자가 새로 구성한 진단이며 독립 전문가 평가나 완전한 블라인드 자료가 아닙니다.

배정 계약은 2건 실패했지만 실제 핵심 답변을 읽으니 더 많은 오류가 있었습니다. 마무리·문장 다듬기 요청을 놓치고, 비교와 준비 중 하나만 답하며, 마음 돌보기·다음 행동을 누락하거나 분담을 대화로 바꿨습니다. 수동 마음 돌보기와 혼자 하는 선택지에도 불필요한 대인관계 관점이 붙었습니다. 기계적 통과와 의미 품질은 다릅니다. 첫 실제 출력·요약은 수정하지 않았습니다.

이를 보고 요청 분해·목표 식별·카드 문맥을 수정했습니다. [수정 뒤 128개 실제 출력](../test-results/alignment/regression/review.html)은 회귀 자료이며 최종 구현에 대한 새로운 미사용 평가가 아닙니다. [회귀 계약](../tests/alignment-regression-expectations.json)은 요청 누락과 잘못된 작업 메타데이터를 검사하지만 자연스러움이나 전문성을 점수화하지 않습니다. 모든 128개 상세 변형을 직접 읽었다고 주장하지 않으며 실제 범위는 별도 기록합니다.

## 검증 범위와 한계

[최종 검사 묶음](../test-results/v85-validation.json)에 전체 실행 결과를 연결합니다. 기존 스트레스 조합 1,024회·질문 320개·통합 출력 72회와 v83/v84 자료는 알려진 회귀 자료입니다. 단위 속성·카드 조합 검사도 새 질문 수나 전문가 품질 점수로 세지 않습니다. 과거의 두 분야 라벨 불일치를 유지하며, 명시적인 마음 돌보기 요청을 emotion으로 읽으면서 과거 action 정답과 다른 엄격한 라벨 결과도 숨기지 않습니다. 요청·사실 보존과 분류 라벨의 차이를 별도로 검토합니다.

기존 320개 중 후보에서 바뀐 핵심 답변 67개를 읽었습니다. 실제로 편집하는 대상이 무엇인지보다 ‘편집’이라는 동사만 보고 영상 편집을 사실 문서 검증으로 바꾸는 퇴행과, 감정 진술을 비교 요청으로 바꾸는 퇴행을 찾아 보완했습니다. [검토한 실제 수정 전후 문장과 최종 차이](../test-results/editorial/v85-review.html), [직접 검토 범위](../test-results/editorial/v85-review.json)를 남깁니다. 전체 320개의 모든 상세 설명을 이번 버전에서 직접 읽었다는 뜻은 아닙니다.

기기 검사에는 기존 자동 설정 외에 복합 요청과 수동 분야·초점을 추가했습니다. 세 Chromium 화면 프로필에서 80개 질문·카드·설정 조합의 전체 보고서와 오프라인 실행을 대조했습니다. main 병합 `03da9c2`와 Pages 배포 성공 뒤 [실제 공개 주소 검사 7개](../test-results/public-85-check.json)도 통과했습니다. 새 두 프로필 각각의 HTML 캐시 해시와 오프라인 80개 전체 해석이 로컬 검증본과 같았고 원본 78장도 표시됐습니다. 모바일 프로필은 실제 휴대전화나 Safari 검증이 아닙니다.

새 질문에서도 도자기 유약·합창 연습·창작 문장처럼 대상에 특화된 해석과 실천은 일반적입니다. 첫 평가 16번처럼 한 절 안에 있는 확인한 날짜/미확인 장소를 나누어 준비 조언에 적용하는 능력은 아직 부족합니다. 카드 이름과 주제의 반복도 남습니다. 새 분야·낯선 말투·생략·긴 복합 요구를 모두 이해하지 못하며 독립 전문가 검증도 아직 없습니다. 핵심 품질과 실제 외부 기기 목표를 완수한 뒤 한국어·일본어·영어 번역을 진행한다는 순서를 유지합니다.
