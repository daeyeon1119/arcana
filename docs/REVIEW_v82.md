# v82 · 질문 근거·시간·복합 요청

## 실제 동작의 변화

질문을 카드와 독립적으로 읽는 `src/question-model.js`를 추가했습니다. 요청, 사건, 주체·수신 방향, 부정·조건·계획·전언, 시간 범위와 공백·유니코드 정규화 후의 원문 위치를 보존합니다. 상태를 ‘참/거짓/알 수 없음’으로 나누고, 문장에 단어가 있다는 이유만으로 이미 일어난 사실로 처리하지 않습니다. 이 모듈은 **제한된 한국어 문법 파서**이며 범용 언어모델이 아닙니다.

`src/reading-context.js`는 이 근거를 기존 리딩과 연결합니다. 사용자가 보낸 답장과 받은 답장, 전해 들은 발표와 직접 확인한 결과, 예정된 평가와 완료 뒤 결과 대기, 지난 결과와 다음 평가를 구분합니다. 사건의 원문 구간은 검토 자료에서 확인할 수 있습니다. 사건의 `completed` 표지는 완료형 표현의 유무이며, 실제 상태는 주장·조건·전언 등의 표지와 함께 계산합니다.

비교와 결정 후 행동, 준비와 감정 돌봄처럼 함께 요청한 관점을 보고서에 따로 반영합니다. 카드·정역방향·배열 위치는 그대로 사용하며 저장 기록과 텍스트 내보내기도 같은 답변을 사용합니다. 직접 선택한 답변 초점은 유지합니다.

지시어와 일반적인 질문 표현뿐이어서 상황을 알 수 없을 때는 **카드를 뽑기 전에 한두 문장의 보충 상황을 묻습니다.** 원래 질문을 바꾸면 미완성 보충 상황도 지워서 다른 질문에 섞이지 않게 했습니다. 빈 질문으로 오늘의 성찰을 시작하는 동작은 유지합니다.

외부 전문가 평가가 아니며, 같은 분류를 배열 수만큼 중복해서 정답으로 세지 않았습니다. 첫 후보는 다른 사람의 발신을 사용자의 수신으로 바꾸고, 아직 면접 전인데 완료된 절차라고 말하는 새 퇴행을 만들었습니다. 최초 결과를 보고 발신·수신의 첫 동사, 후속 절의 부정, 예정·완료와 결과 확인 상태를 수정했습니다. **수정 후 점수는 새 독립 평가가 아닙니다.**

분류가 맞아도 실제 조언은 틀릴 수 있었습니다. 예를 들어 사용자가 동생에게 답장했지만 동생의 답은 아직 없는 상황에서, 처음에는 상대가 전한 내용에 먼저 답하라고 했습니다. 결정 후 첫 행동을 비교 문장으로 다시 채운 경우도 있었습니다. 이 두 문제는 실제 문장을 읽어 찾았고 회귀 검사에 추가했습니다.

## 남은 한계와 다음 방향

- 진료 대화 준비에 일반적인 진단 주의 문구가 큰 비중을 차지하고, 저축 조건 확인 질문에 지출 절감 조언이 남는 등 실제 요청과 조언의 거리가 남아 있습니다.
- 새 상황 `u23`은 관계 성찰인데 기존 분야 판별이 일·진로로 읽어 직장 맥락 문장이 나옵니다. 이번 평가의 분류 기대값을 비워 둔 항목이라 점수만 보면 이 오류를 놓칩니다.
- 여러 문장의 주체가 생략되거나 시간 범위가 겹치는 질문, 서로 연결어가 없는 여러 요청, 새로운 말투와 표현은 추가 검증이 필요합니다.
- 구체적인 조언이 카드의 미묘한 차이까지 항상 반영하는지, 여러 카드 전체가 만드는 하나의 해석이 충분히 설득력 있는지도 별도 검토가 필요합니다.

특정 질문에서만 통과하는 분기 추가를 성공 기준으로 삼지 않습니다. 다음 단계는 이 근거·요청 구조와 검증을 유지하면서 자유로운 표현을 이해하는 의미 해석 계층을 넓히는 것입니다. 모델을 연동할 경우 실제 질문·원본 카드·정역방향·위치·알려진 사실·알 수 없는 것을 함께 전달하고 결과를 검증해야 합니다. 외부 처리·비용·운영 방식도 구현과 함께 명시해야 합니다.

전문 타로 해석가와의 독립 비교를 수행한 것은 아닙니다. 최종 목표는 아직 달성·검증되지 않았습니다.
