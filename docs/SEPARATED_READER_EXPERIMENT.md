# 질문 답변과 카드 관점의 분리 후보

카드 없이 질문의 요청별 실질적인 도움을 먼저 생성하고, 다음 단계는 카드별 관점과 연결만 추가하는 실험 코드입니다. 두 번째 단계가 첫 답변·실천을 덮어쓰지 못하도록 별도 출력 계약을 사용합니다. 두 단계의 첫 원문도 따로 보존합니다.

합성 계약 검사 25개와 별도로, Qwen3.5-9B의 **기존 개발 질문 1개**를 실제 생성해 초안·카드 관점 전체를 읽었습니다. [첫 실제 답변](../test-results/local-reader/native-qwen35-9b-separated-first/development-v1/review.html)은 구조 검사에 통과했지만 의미 품질은 채택 기준에 미달했습니다. 첫 초안은 배경을 요청으로 고르고 확인 전이라는 상태를 조건 미확정으로 바꿨으며, 카드 관점에는 과거 저축 시도와 현재 재정 불안을 지어내는 문제가 남았습니다. 기본 앱과 빌드에 포함하지 않았습니다.

질문 도움에 약 255.4초, 카드 관점을 포함한 전체에 약 451.2초가 걸렸습니다. 같은 기기의 실제 첫 출력이며 다른 기기의 속도를 보장하지 않습니다. 질문을 반복 수정하거나 좋은 재시도만 선택하지 않았습니다. 새 질문 14개는 이 후보에서 실행하지 않았습니다. 이 개발 질문 한 개로 새 질문의 일반화나 전문가 수준을 주장하지 않습니다.

검사 25개는 두 번째 단계가 첫 답변을 바꾸지 못하는 구조를 확인할 뿐, 초안이나 카드 문장의 의미가 맞는지 판별하지 않습니다. 보고서는 초안만 받은 경우와 완성된 해석을 분리합니다. 해당 도구 검사는 합성 자료이며 실제 질문 평가로 세지 않습니다.

사용자가 외부 기기에서도 동일 수준의 작동을 요구했으므로 이 PC의 대용량 모델만으로 제품 목표를 달성했다고 인정하지 않습니다. 이 후보는 앱에 포함하지 않는 진단 모듈과 실제 실패 기록으로 보존합니다. 향후 채택은 실제 해석 품질과 외부 기기에서 이용 가능한 동일 경로를 함께 검증해야 합니다.

공개 웹 앱의 오프라인·배포 검사는 완료했고 해석 엔진은 v82를 유지합니다. 다음 정식 개선은 특정 질문의 정답 대체가 아니라 **사용자가 요청한 작업을 분야별 일반 조언보다 먼저 다루는 경로**에 초점을 둡니다. 설명·조건 확인·대화 준비 같은 요청을 건강·금전 단어만으로 진단/투자 경고나 생활비 조언으로 바꾸는 구조를 점검해야 합니다.

2026-10-27에 확인한 [Hugging Face Spaces 문서](https://huggingface.co/docs/hub/spaces-overview#hardware-resources)는 CPU Basic의 시간당 비용이 없더라도 새 Gradio/Docker Space 생성에는 유료 플랜이 필요하다고 명시합니다. 유료 서비스를 사용하지 않는 원칙에 따라 무료 공유 추론 서버라고 간주하지 않습니다. [Transformers.js](https://huggingface.co/docs/transformers.js/index)는 브라우저 CPU/WASM 경로를 제공하지만, [Qwen3.5-0.8B ONNX 후보 예시](https://huggingface.co/onnx-community/Qwen3.5-0.8B-ONNX-OPT)는 WebGPU를 사용합니다. 해당 모델의 CPU 경로·모바일 작동·해석 품질을 실행으로 확인한 것은 아닙니다. 작은 모델을 다운로드하거나 정식 기능에 추가하지 않았습니다.
