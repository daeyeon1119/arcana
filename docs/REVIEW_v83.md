# v83 후보 · 질문에서 요청한 작업 우선

현재는 검증 중인 후보이며 아직 정식 배포한 결과가 아닙니다. 해석 엔진을 무료·오프라인 JavaScript 안에서 보완하므로 특정 PC의 모델이나 유료 API를 요구하지 않습니다. 원본 RWS 78장과 8종 배열은 유지합니다.

## 개선하는 구조

분야는 건강·금전인데 사용자가 원하는 것은 설명·조건 확인·질문 준비·마음 돌보기인 경우, 기존 분야별 주의문이 실제 요청을 덮는 문제가 있습니다. 요청한 작업을 먼저 식별하고, 기존 맥락별 조언 가운데 작업이 맞는 것을 선택한 뒤 실제 카드 근거를 연결합니다. 기존 조언이 잘 맞으면 구체성을 버리고 일반 문장으로 교체하지 않습니다.

배경의 ‘바꾸려면·시작할 때’와 실제로 묻는 동사를 구별합니다. 실제 요청이 ‘어떻게 할까요’처럼 생략됐을 때는 명시된 목적을 이어받습니다. ‘나누다·조정하다’는 단어만으로 분담·우선순위를 정하지 않고 그 대상도 확인합니다. 인용문은 요청이나 사실의 근거로 다시 사용하지 않습니다.

작업별 기존 조언의 출처를 기록합니다. 역할을 조율하는 말은 대화 요청에 활용할 수 있고, 실제 담당자·성과 같은 준비 내용이 있는 조언은 협상의 근거 준비에 활용할 수 있습니다. 기존 카드 통합 해석도 함께 유지합니다. 정보가 부족한 상태에서 새로운 과거·현재 사실이나 협업 상대를 만들지 않습니다.

이는 제한된 한국어 규칙과 편집한 조언입니다. 범용 언어 이해나 전문가 동등성의 증거가 아닙니다. 모든 질문을 이해했다고 주장하지 않습니다.

## 개발 검토와 별도 첫 평가

구현 전후의 기존 320개 질문을 재생성했습니다. 자동 검사 통과 뒤에도 바뀐 문장을 직접 읽으며, 배경 동사를 실제 작업으로 오해하거나 구체적인 조언을 일반 문장으로 바꾸는 퇴행을 찾았습니다. 이 자료를 보고 수정했으므로 개발·회귀 자료입니다. 단위 검사와 개발 질문 12개 × 배열 8종도 독립 평가로 세지 않습니다.

구현을 커밋으로 고정한 다음 별도의 질문을 작성하고, 같은 카드·정역방향·배열에서 v82.1과 후보의 실제 출력을 남깁니다. 첫 결과는 덮어쓰지 않습니다. 첫 평가를 보고 수정할 경우 이후 재생성은 회귀 자료로 구분합니다. 질문별 핵심 답변과 선택한 배열의 상세 카드 설명을 읽고 실제 검토 범위를 따로 적습니다. 라우팅·참조 검사 수를 의미 품질 점수로 표시하지 않습니다.

응급·연락 거절·위험 상황과 약·치료 변경 같은 임상 판단은 기존 제한을 유지합니다. PC·모바일 화면과 공개 배포의 동일 버전·입력 일치도 다시 확인해야 합니다. 실제 휴대전화·Safari와 전문 해석가의 독립 평가는 아직 없습니다.
